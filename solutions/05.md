## Exercise 2

States after E0…E5 are BUSY, DONE, IDLE, BUSY, DONE, IDLE. done is high in the cycles following E1 and E4. Continuous start causes repeated transactions under this specification, not a single transaction.

## Exercise 3

A safety claim is: outside reset, if done is high in one cycle, it must be low in the next. In this FSM, DONE always transitions to IDLE. Assuming done is always low would exclude the stuck-high behavior and make the check vacuous. Assuming start is always zero can also prevent meaningful transaction coverage after reset. Add a reachability check showing a transaction can complete.
